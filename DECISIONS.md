## 2026-09-27 — lane 3 (F8 quotas and cost logging, F12 admin dashboard)

| # | Decision | Why |
|---|---|---|
| 26 | The quota day boundary is computed with `Intl.DateTimeFormat`, not a date library or an offset table. | `usageDateFor(tz, at)` formats the instant in the family's zone; `nextLocalMidnight` solves for the offset in effect *at the target local time* (two passes), which is what makes DST-transition days come out right. No dependency, and it cannot go stale when a government moves a DST boundary. |
| 27 | An unknown `families.timezone` falls back to **UTC with a warning**, never an error. | A bad timezone string must not be the reason a child does not get a bedtime story. The column is free text with a `'UTC'` default, so a typo is a plausible production state. |
| 28 | The daily quota increment lives in a Postgres function, `consume_daily_quota(family, date, limit)`, revoked from `anon` and `authenticated`. | `insert ... on conflict do update set count = count + 1 where count < limit` makes the increment and the limit check one atomic statement, so two racing requests at count = 2 cannot both become 3. PostgREST's `upsert` cannot express `count = count + 1`, so a function it is. Revoking execute closes the second way a client could move its own quota (RLS already blocks the first). |
| 29 | `DAILY_BUDGET_USD` is a **global cap measured over the database day (UTC)**, not per family and not per family timezone. | It bounds the owner's bill, and there is no single family whose timezone a global cap could key off. Spend comes from the `v_budget_today` view, never an in-process counter — a counter would reset on every cold start and disagree between lambdas. |
| 30 | `GENERATION_ENABLED` and `DAILY_BUDGET_USD` are read from `process.env` on **every call**, not from the cached `serverEnv()` snapshot. | F8 AC: "take effect without a deploy". Caveat worth stating plainly: on Vercel, changing an env var still needs a redeploy before the running function sees it, so the switch is only as live as the platform makes it. The code is not the limiting factor. |
| 31 | `GENERATION_ENABLED` **fails safe (on)** when the value does not parse; `DAILY_BUDGET_USD` falls back to $5. | A typo in an env var must not silently take the product down. An operator deliberately turning generation off will write a value that parses. |
| 32 | A `generation_logs` insert failure is **logged and swallowed**, never thrown. | `callModel()` awaits the sink from inside its own catch block, so a throwing sink would replace the real `ModelCallError` and lose the cause of the failure. A story that generated but was not logged beats a story that failed because logging did. The miss is loud on stderr and counted in `SupabaseLogSink.failedWrites`. |
| 33 | Migration `20260927000005` **revokes the admin views from `anon` and `authenticated`** and sets `security_invoker = on` on all of them. | The F12 views were world-readable: they are owned by `postgres`, so they bypassed RLS on `generation_logs`, and the public schema's default grants gave every client SELECT. `curl` with the anon key returned the day's spend. The dashboard reads with the service role, so revoking costs the app nothing. `v_top_topics` stays readable by `authenticated` — F10 sources its suggested-topic chips from it — but with `security_invoker` so `fact_packs`' own `status = 'ready'` policy applies. |
| 34 | The dashboard's headline median comes from a **new** `v_story_cost_summary`, which excludes stories with no log rows. | `v_cost_summary` left-joins `generation_logs`, so a story row written without logs (a seed, a fixture, another lane's test) enters the distribution at $0 and drags the median down. Both numbers are shown so the gap is visible. The existing view is untouched — it is applied elsewhere. |
| 35 | Cost per story is attributed to a writing model through `v_story_writer` (the most expensive `write`/`rewrite` row on the story), and every model is judged against **its own** expected median. | Haiku 4.5 tokenizes ~30% shorter than Sonnet 5 / Opus 5.5 / Fable 5.1 for identical text, so any cross-model comparison has to reconcile against measured tokens. Judging all models against one expected figure would label Haiku "below band" and Fable "above band" for ever. |
| 36 | `lib/costs/expected.ts` derives the expected cost per story from the §5 token table and `config/pricing.json`; no dollar figure is hard-coded. | It is the yardstick /admin compares the measured median against, so it has to move when a price moves. Confirmed against the four medians in the lane brief: $0.0445 Haiku 4.5, $0.0714 Sonnet 5, $0.1244 Opus 5.5, $0.2836 Fable 5.1. |
| 37 | The "~70% output tokens" figure is the **write call's** output share for the configured Sonnet 5 writer, and is not a constant across models. | Measured from the §5 table: all-output share runs 66% (Haiku) → 76% (Sonnet 5) → 84% (Opus 5.5) → 90% (Fable 5.1), because the input-heavy helper calls stay on Haiku whatever the writer is. Sonnet's write-output share is 70.1%, which is where the figure comes from. Nothing in the codebase should treat 70% as universal. |
| 38 | Limit refusal copy lives in `lib/limits/messages.ts`, not `config/guardrails/messages.json`. | Quota, kill switch and budget are capacity and cost limits, not guardrail refusals. If lane 5's file grows keys for these three, that file wins and these become the fallback. |
| 39 | `instrumentation.ts` installs the Supabase log sink at server boot. | One place, so no call site can forget, and it runs before any route. Guarded to the Node.js runtime — the Edge runtime has no service-role client. |

## 2026-09-27 — F15 guardrails (lane 6)

| # | Decision | Why |
|---|---|---|
| 60 | The L1 hard blocklist carries the **action, not the noun**: "make a bomb" is a term, bare "bomb" is not. Likewise "nazi", "hitler", "holocaust", "massacre", "terrorism", "slavery" and "dynamite" are deliberately absent from L1. | Every one of those is a real educational topic for an older band ("the atomic bomb", "how the Second World War started", "who invented dynamite"), and GUARDRAILS.md §3.3 puts wars and historical injustice under *allow_with_care*, not refuse. A hard L1 refusal on a history word is a false refusal a parent notices immediately, and §1.1 says each layer is allowed to be imperfect because the others catch what it misses. The semantic call is L2's. |
| 61 | Blocklist matching uses a **compiled guarded pattern** per term — letter-boundary lookarounds, repeated letters, leetspeak homoglyphs, and separator tolerance for terms of 4+ letters — plus NFKC folding, diacritic folding and a phrase allowlist masked out before matching. Every match must contain at least one real letter. | §3.2 asks for word-boundary matching *and* §6 asks the corpus to defeat spacing, symbol and leetspeak obfuscation. Substring matching satisfies the second and breaks "Scunthorpe"; plain `\b` satisfies the first and loses to "b o m b". The lookaround form does both, and `\b` specifically cannot be used because the leet variants include `$`, `@` and `|`, where `\b` flips meaning. The real-letter rule stops "4 55" being read as a slur. |
| 62 | The **story-side** hard checks are violent *phrases in context*; bare emotive words ("blood", "dead", "gun", "kiss", "monster") are `soft` violations that never fail a story on their own and are instead handed to the Haiku review as things to check. | Calibration against the reference stories, which are the quality bar: the band A shark story contains "a tiny drop of blood", the band C video-games story contains "people who liked shooting things" and "brought video games back from the dead". §4.2's word list plus §4.3's "any hard violation fails" would fail two of the four reference stories. §4.3's model review is where judgement belongs. |
| 63 | A chapter ending in an ellipsis raises a `cliffhanger_marker` check and a **soft** rule 3 violation, and is exempt entirely when the ellipsis follows an all-caps sound effect. | The shark reference ends a band A chapter with "the whole ocean went **WHOOOOSH**..." — a transition, not dread. §4.2's marker rule is a useful signal, but whether a trailing ellipsis is a dread cliffhanger is a judgement; rule 3's real cliffhangers ("it was right behind him") are caught by the hard phrase list regardless. |
| 64 | Rule 7 fires on a branded character **taking part** — acting, speaking, or accompanying the children — not on the name appearing. | §4.1 rule 7 states the boundary itself ("Mario started life as Jumpman" is fine, Mario helping the kids is not), and the video-games reference relies on it: it mentions Mario, Pac-Man and Jumpman factually eight times. Name matching would fail the reference story. |
| 65 | Rule 6 needs a **name plus an identifying detail** (address, phone, workplace, school) before it hard-fails. | "Their teacher, Miss Patel, showed them a map" is an ordinary incidental character; "their neighbour Mrs Atkins of 14 Elm Road" is a real private individual. Deterministically the difference is the identifying detail, so that is what the check looks for. Everything subtler is the Haiku reviewer's call. |
| 66 | The **age band is enforced in code as well as in the classifier prompt**: an `allow_with_care` whose `min_recommended_age` exceeds the youngest child is rewritten to `refuse` / `too_mature_for_band`. | §3.3 asks the classifier to do this itself, but then the Titanic-at-4 behaviour would be a property of one model call. `applyAgeBand()` makes it a property of the system, which is what the corpus asserts. |
| 67 | The classifier's own `parent_message` is **validated before a parent sees it** — no 4-gram echo of the input, no blocklist hit, no injection, no PII, no mention of layers or machinery — and falls back to the template in `config/guardrails/messages.json` otherwise. | §5 forbids echoing the offending text and revealing the layer. That is a hard requirement, and a model-written string cannot be trusted to honour it. The model's version is better copy when it is safe, so it is used when it passes. |
| 68 | An L2 response that fails to validate **fails closed**: refuse, category `other`, template message. Likewise an unparseable safety review returns `safe: false, scary_level: 3`. | §1.3, "fail closed on output, fail kind on input". A parse failure must never become a silent allow. |
| 69 | The L2 classifier constrains its JSON by **prompt instruction plus zod validation**, not `output_config.format`. | Structured outputs are documented as available, but Haiku 4.5's support could not be verified live in this environment and `callModel()` already validates and can repair. A wrong `output_config` shape would 400 on the nightly live run for no benefit. Enabling it is a one-line change once verified — see the note in `lib/guardrails/classify.ts`. |
| 70 | Profanity has no category in the §3.3 enum, so it is logged as `other`. | The enum is a cross-lane contract in `lib/schemas/` and must not be widened without the owner's sign-off. `other` carries it without a schema change. |
| 71 | Prompt files are authored as documents with `## System prompt` / `## Output` / `## User message` sections, and `lib/guardrails/prompts.ts` extracts the model-facing sections. | CLAUDE.md rule 5 wants prompts in `prompts/*.md` with a version header; a reviewable prompt needs rationale that must not be sent to the model. Extraction keeps both, and the bytes sent stay stable so prompt caching still hits. |
